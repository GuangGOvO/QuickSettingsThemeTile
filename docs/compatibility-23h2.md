# Windows 11 23H2 x64 compatibility evidence

Snapshot date: 2026-10-16. This record investigates whether the existing `ControlCenter.dll` adapter has a candidate for Windows 11 23H2 x64. It does not add or approve a runtime profile.

## Release identity

Microsoft's October 13, 2026 KB5126653 support article title identifies the update as OS build **22621.7652**, while the Windows 11 release-information table lists the 23H2 latest build as **22631.7652**. The article applies to all 23H2 editions and says 23H2 is enabled with KB5027397. Because Microsoft states that 22H2 and 23H2 share a common core and system-file set, retain this label discrepancy rather than using either build number as a DLL compatibility signal. [KB5126653](https://support.microsoft.com/en-us/servicing/os/windows-11/2026/10/kb5126653-windows-11-23h2-security-update), [Windows 11 release information](https://learn.microsoft.com/en-us/windows/release-health/windows11-release-information), [KB5027397](https://support.microsoft.com/en-us/servicing/os/windows-11/2023/05/kb5027397-feature-update-to-windows-11-version-23h2-by-using-an-enablement-package).

## Evidence collected

- The x64 KB5126653 MSU from Microsoft Update Catalog is 1,222,962,623 bytes, SHA-256 `98F3FCE8D9ECA7DD90B5A6F86BAA1DBAE0A44E5E2881266BD895104713DCC84B`, and has a valid Microsoft Corporation Authenticode signature.
- The update's `express.psf.cix.xml` index and Microsoft's [KB5126653 file-information CSV](https://download.microsoft.com/download/16ba8bf1-c975-4501-9df6-a5089719ef46/5126653.csv) contain no `ControlCenter.dll` entry. The CSV has 102,617 rows and SHA-256 `912B27AF501A793575A1C9D72C19849EAD50FED4C8D60ADD5775DEA901256021`. These are update-payload inventories, not complete inventories of every unchanged file already installed on a device.
- `tools/compat-discover.ps1 -Build 22621.7652` returns no AMD64 `ControlCenter.dll` association from the current Winbindex dataset. This is a missing public candidate, not proof that a particular host lacks the DLL.
- As a historical baseline, the UUP Dump API's [stable 22H2 22621.1 record](https://api.uupdump.net/get.php?id=356c1621-04e7-4e66-8928-03a687c3db73&lang=en-us&edition=professional&noLinks=1) identified a Professional image ESD with SHA-256 `29CED52B2B659D5BA353108D9EC4B243B3B5D99529058C38E97CAAFF051EC041`. A local 7-Zip archive listing found `QuickActionsDataModel.dll` and `Windows.UI.QuickActions.dll` paths, but no `ControlCenter.dll` path. UUP Dump is a third-party index; this baseline listing is supporting evidence only. Extracting the ESD's individual DLL payload failed, and DISM reported that image inspection requires elevation, which was not requested or attempted.
- The 2026-10-16 Winbindex metadata associates the KB5126653 23H2 update with `QuickActionsDataModel.dll` hash `E1DCED161D92F86B8F5BE8EFC072439C5BBDEF0E4A9C52CBACFD911E84B5EA35`, `Windows.UI.QuickActions.dll` hash `74DB8B97C779F07B3875037C44F583C6677D5F8C3A1A5CB2E81D5CDC84908CF9`, and `CustomShellHost.exe` hash `1CE86F1A3F6570F08941D66AB108C2C073316F65F6C10E5EC5BCC3490A0C8B18`. These are third-party index associations and do not replace verifying the exact bytes from the signed update package.
- A Microsoft symbol-server request for `QuickActionsDataModel.dll` using the indexed timestamp/image-size key returned a 409,600-byte PE with the same timestamp and image size but SHA-256 `ACF5B7DBAFAAA76BD6FCA846EBBE910BC39BDD4A54C01A0EEC4A51F453045C02`, which does not match the Winbindex hash above. Its embedded PDB identity was readable, and its public symbols included `Windows::Internal::QuickActions::QuickActionsProvider` and `QuickSettingDefinition::MakeQuickAction`; because the PE hash differs, this symbol review is only an architecture clue, not proof about the exact KB5126653 candidate.

## Compatibility decision

The current update index points to a distinct Quick Actions data-model and host stack rather than an AMD64 `ControlCenter.dll` candidate. The symbol-server PE mismatch also prevents using that PDB as exact-binary proof. Therefore 23H2 remains **unsupported and unverified** by this `ControlCenter.dll` adapter. No legacy candidate was loaded into Shell, and the active host was not changed.

## 22621.1 legacy baseline sample

A local 22621.1 x64 baseline sample extracted from the `Microsoft-Windows-Client-Desktop-Required-Package.ESD` has `QuickActionsDataModel.dll` SHA-256 `488A3C2B39A8A5403634196D512AB9B5640F94FFDE9BF270CB0D37C10C837C30` (405,504 bytes), PDB GUID/Age `{9B3E135C-D340-4236-59DF-CBD5B35A085D}`/1. Its identity-matched Microsoft public PDB exposes `QuickActionsProvider::Initialize`, `get_AvailableQuickActions`, `QuickSettingDefinition::MakeQuickAction`, and `ControlCenterSettings::ReadQuickActionsList`. This supports the conclusion that 22H2-era Quick Actions uses a separate provider/data-model contract. It does not establish the ABI in a current 23H2 servicing build or explain how a third-party model can safely join the native, reorderable collection; the sample was never loaded into Shell.

The unresolved 26100.4202–4351 `ControlCenter.dll` candidate also received a full redownload from Microsoft's symbol server. The PDB parser reports the matching GUID but age 3, whereas the DLL CodeView record requires age 1. Because the exact PDB identity cannot be verified, this candidate remains unknown and is not used to infer an RVA.

To close this gap, verify the exact DLLs from the signed KB5126653 package or a complete 23H2 x64 image, identify the old provider/host contract, then assess it in a disposable 22631 VM. The current adapter must not reuse a newer profile based on similar symbol names, PE metadata, or the fact that 22H2 and 23H2 share system files.
